# DeadlinePilot ― 学生エンジニア向け締切管理エージェント

Kaggle・AtCoder・ハッカソン・奨学金・インターン選考。学生エンジニアは常に
数十の締切を抱えていますが、その情報は告知メール・公式ページ・Discordに
散在し、手作業での管理に頼っています。AoE・UTC・JST・PT といった
タイムゾーンの取り違えや、登録漏れによる機会損失は珍しくありません。
しかも締切は後から延長・変更されるのに、一度メモした締切を見直す人は
ほとんどいません。

DeadlinePilot は、ユーザーが登録した URL や貼り付けたメール本文を
Google ADK の Planner エージェント（Gemini 2.5 Flash）が自律的に処理し、
締切・必要アクション・タイムゾーンを抽出。zoneinfo による決定的な
正規化で JST に統一し、矛盾や時間衝突を検出して、優先度つきの
締切一覧と行動提案を作ります。

さらに、登録した公式ページは **Cloud Scheduler が6時間ごとに自動巡回**。
ページの指紋が変わったときだけエージェントが起動し、既存の締切と照合して
「締切が 11/21 20:59 → 11/28 20:59 に延長されました」と人間に報告します。
変化がなければ LLM を呼ばないため、常時監視でもトークン消費はゼロです。

**「使える」ための設計**

- **制御された自律性**: 使えるツールは allowlist 化した7種のみ。
  fetch_page はドメイン allowlist 制。1実行あたりツール20回・
  トークン20万・240秒タイムアウトのガバナンスを Runner が強制します。
- **プロンプトインジェクション対策**: 外部テキストは区切りタグで隔離した上、
  ヒューリスティック＋Gemini分類器の二層で「指示文の混入」を検出。
  検知したソースは隔離され、エージェントに本文は渡りません。
- **人間の承認ゲート**: カレンダー登録・リマインド等の外部書き込みは
  エージェントが「提案」のみ作成し、UI で人間が承認したものだけ実行
  （ICS ダウンロード等）。却下も記録されます。
- **可観測性**: エージェントは各ツールの前に「なぜ呼ぶか」を1文で述べ、
  実行中の様子は UI にライブ表示されます。各ステップ（判断理由・ツール入出力・所要時間・トークン数・
  推定コスト）を Firestore と Cloud Logging に記録し、「実行トレース」
  画面でタイムライン表示。成功/失敗・注入検知・承認数の統計ビューも。
- **再評価ループ**: confidence 低下やソース間矛盾があれば別ソースを
  追加取得して再検証し、決着しなければ「要確認」として人間に返します。

Cloud Run（フロント・バックエンド）＋ Vertex AI Gemini 2.5 Flash ＋
Firestore ＋ Secret Manager ＋ Cloud Scheduler 構成。min-instances=0 と軽量モデル使い分け
（分類器は Flash-Lite）で、個人利用なら月数円〜数十円の費用対効果です。

## 動作確認の方法（提出フォーム用）

テストアカウント: ID `judge` ／ パスワードは提出フォームに記載。
ログイン後、サンプル締切12件・未処理ソース3件・承認待ち提案1件が表示されます。

1. **締切一覧**: 「今やるべきこと」と、AoE/UTC/PT 表記の締切が JST に統一された一覧。
2. **ソース登録 → 「未処理 3 件をエージェント実行」**: 実行の様子がライブ表示されます
   （約1分）。注入メールは隔離され、正常メールの締切が登録されます。
3. **変更監視**: 同じ画面の「主催者が締切を1週間延長する」→「今すぐ巡回」。
   エージェントが変更を検知し、締切一覧に「変更あり（旧 → 新）」、承認待ちに報告が届きます。
   延長前に「今すぐ巡回」を押すと、変化なしで LLM を呼ばずに終了する様子も確認できます。
4. **承認待ち**: 提案を承認すると ICS をダウンロードできます（外部書き込みは承認後のみ）。
5. **実行トレース／統計**: 判断理由・ツール・トークン・推定費用・注入検知数を確認できます。
