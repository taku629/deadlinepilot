# 振り返り：第5回 Agentic AI Hackathon with Google Cloud

## 結果

- 提出: 2026-10-15 22:38 JST（提出数 229 件）
- 結果: 1次審査で終了（2次審査には進めず）
- 運営からの通知に、具体的な理由や講評はありませんでした

以下は、公式の審査基準と公開されている提出作品を照らし合わせた**自己分析**です。

## 審査基準

1. 課題の新規性と解決策の有効性
2. 自律性・エージェントらしさ
3. 実装品質と拡張性

規約上、1次審査では全提出物を精査するとは限りません。
つまり、プロジェクトページ（説明文・画像・構成図）とデモ動画で大半が決まると考えるべきでした。

## うまくいかなかったと考える点

### 1. 課題の新規性が伝わりにくかった（最も大きい）

- 基準は「多くの人が抱えながらも、いまだ解決策が与えられていない課題」。
  「締切管理」と聞くと、カレンダーやタスク管理アプリで足りると受け取られやすい。
- 本当の差分（**後からの締切延長を見張る**、タイムゾーンの決定的な正規化）が、
  タイトルと説明文の冒頭で前に出ていなかった。
- 同じ回に予定・締切系の作品が10件ほどあり、テーマとして埋もれた。
- 対象を「学生エンジニア」と狭く書いたため、「多くの人」という軸からも少しずれた。

### 2. 1次審査で見られる部分が薄かった

- プロジェクトページの画像が0枚。229件中205件は画像を載せていた。
- Zenn 記事なし（任意だが72件は投稿）。設計の工夫を読ませる場がなかった。
- デモ動画は締切の約1時間前に完成。冒頭で一番の売りを見せ切れていたか検証できなかった。

### 3. 「単純な自動化を超えたエージェントらしさ」が見えにくかった

- 外から見ると「抽出＋タイムゾーン変換＋定期監視」のパイプラインに見えやすい。
- 実際には Planner がツール順を判断し、矛盾時に別ソースで再検証するが、
  その判断の場面を画面とページで目立たせていなかった。

### 4. 開発期間が短かった

- 着手から提出まで約3日。8月から作り込んでいる参加者も多い中で、見せ方の磨き込みに時間を割けなかった。

## 良かった点

- 今回のテーマ（ガバナンス・可観測性・注入対策）には正面から応えていた。
- 変化がなければ LLM を呼ばない設計で、常時監視でもコストがほぼゼロ。
- デプロイ・テストアカウント・サンプルデータ・構成図・動画など、必須要件はすべて満たした。

## 次のハッカソンでやること

1. 「既存ツールがない」と一言で言える課題を選び、タイトルと説明文の1行目で言い切る
2. プロジェクトページにスクリーンショット3〜5枚（主画面・エージェントの判断過程・構成図）
3. デモ動画は最初の30秒で「何がすごいか」を見せ、締切の前日までに完成させる
4. Zenn 記事も出す
5. エージェントが自律的に判断する場面（再検証・人間への差し戻し）を画面で見せる
6. 締切の1週間前に機能を凍結し、残りは見せ方に使う
